1. Executive Summary & Objective

This Incident Response Report documents the security investigation performed for Project 04: Security Monitoring & Incident Response. Security Operations Centers (SOC) continuously monitor organizational infrastructure to identify malicious activities hidden within legitimate system noise.

The objective of this analysis is to evaluate system access logs, differentiate normal operational baseline activity from suspicious anomalies, construct robust detection rules (SIGMA/SIEM pseudo-logic), classify security incidents based on severity metrics, and provide structured remediation workflows based on industry frameworks (NIST SP 800-61 / ISO 27035).

2. Log Analysis & Anomalies Identified

During the log forensic analysis, event logs were categorized into normal system baseline operations and potential threat vectors. Below is a structured analysis of observed behaviors:

A. Normal Operational Baseline vs. Suspicious Events

Event Category Normal Operational Baseline Identified Suspicious Anomaly
Authentication Single successful login attempts by employees during standard working hours (08:00–18:00 IST) from internal corporate IPs (10.0.0.0/8). High-volume failed login attempts (50+ per minute) targeting administrative accounts (e.g., admin, root) followed by a successful login.
IP Geolocation Access requests originating from domestic subnet pools or registered VPN corporate egress gateways. Inbound connection requests from external/unrecognized IP addresses (e.g., 185.220.101.5 - known Tor Exit Node) targeting administrative SSH/RDP ports.
User Privileges & Behavior Users accessing assigned network drives, local HR applications, and standard productivity tools. Unusual off-hours administrative privilege escalation (e.g., sudo su at 03:15 AM) and mass directory enumeration/data archiving (tar -czvf /tmp/exfil.tar.gz).
Network & System Activity Standard HTTPS web traffic (ports 80/443) and internal DNS queries to localized corporate domain controllers. Abnormal outbound traffic spikes over non-standard ports (e.g., TCP 4444) and DNS tunneling queries with long subdomains.

B. Log Findings Summary

  • Brute Force / Credential Stuffing Vector: Log entries revealed repeated Event ID 4625 (Failed log on) occurring rapid-fire from external IP 185.220.101.5 against account admin_user, followed by Event ID 4624 (Successful log on).
  • Anomalous Off-Hours Access: Administrative credentials were utilized at 03:14:22 AM UTC, outside standard shift rosters, executing privilege escalation routines.
  • Suspicious File Execution: Execution of obfuscated PowerShell scripts and creation of executable files in c:\Users\Public\AppData\.

3. Detection Logic Rules

To automate detection and reduce response times, custom detection logic rules have been designed for implementation in SIEM solutions (Splunk, Elastic, or Sentinel).

Rule 1: Multiple Failed Logins Followed by Success (Brute Force Detection)
SELECT source_ip, target_user, COUNT(event_id = 4625) as failed_attempts
FROM Authentication_Logs
WHERE time_window = 5_minutes
GROUP BY source_ip, target_user
HAVING failed_attempts >= 5
AND FOLLOWED_BY (event_id = 4624 WHERE source_ip = source_ip AND target_user = target_user);
Alert Justification: Indicates a potential brute-force or credential-guessing attack that successfully breached an account. Immediate notification ensures account lockouts before unauthorized persistence is established.
Rule 2: Administrative Login from Unknown / External IP
SELECT event_time, user_id, source_ip, location
FROM Access_Logs
WHERE user_role IN ('Domain Admin', 'System Administrator', 'root')
AND source_ip NOT IN (SELECT ip_address FROM Corporate_Trusted_Subnets);
Alert Justification: Administrative access should strictly originate from managed corporate endpoints or VPNs. External administrative logins indicate stolen credentials or unauthorized remote exposure.
Rule 3: Admin Privilege Escalation at Anomalous Hours
SELECT event_id, user_id, process_name, timestamp
FROM Security_Events
WHERE event_type = 'Privilege_Escalation' OR process_name IN ('sudo', 'runas.exe')
AND TIME(timestamp) BETWEEN '23:00:00' AND '05:00:00'
AND user_id NOT IN (SELECT user_id FROM On_Call_Schedule);
Alert Justification: Attackers often perform destructive actions or lateral movement during off-peak hours to avoid active monitoring by human analysts.
Rule 4: High-Frequency Outbound Data Transfer (Data Exfiltration Indicator)
SELECT source_internal_ip, destination_external_ip, SUM(bytes_sent) as total_bytes
FROM Firewall_Traffic_Logs
WHERE direction = 'Outbound' AND time_window = 10_minutes
GROUP BY source_internal_ip, destination_external_ip
HAVING total_bytes > 500MB;
Alert Justification: Rapid exfiltration of corporate data or archives (e.g., .zip, .tar.gz) often generates distinct high-volume outbound telemetry spikes.

4. Incident Classification & Response Matrix

High Severity Successful Brute Force & External Admin Login Full host compromise, unauthorized access to sensitive internal systems, domain persistence. • Immediately isolate affected host from network.
• Force global password reset for compromised account.
• Block malicious source IP at edge firewall.
• Escalate to L2/L3 SOC Incident Handler.
Medium Severity Off-Hours Admin Escalation & PowerShell Script Execution Unauthorized configuration changes, potential malware deployment, privilege misuse. • Contact user/admin to verify legitimate maintenance.
• Kill suspicious PowerShell processes.

Low Severity Isolated Failed Login Attempts (<5 attempts) Minimal immediate risk; potential user mistyping password or minor scanning. • Log event for trend monitoring.
• Monitor for escalation or multi-account brute force.
• No immediate system containment required.

5. Incident Handling Workflow Life-Cycle

The incident management lifecycle follows the standard NIST SP 800-61 Incident Handling Framework across six primary phases:

1. Detection Phase

SIEM generates an alert based on Rule 1 (Brute Force) or Rule 2 (Anomalous IP Admin Login). Log management systems aggregate system logs, firewalls, and endpoint detection agents.

2. Alert Verification & Triage Phase

L1 SOC Analyst reviews alert context, verifies source IP reputation, checks timestamp against maintenance schedules, and confirms whether the alert is a true positive or false positive.

3. Investigation Phase

Analyst cross-references endpoint logs (EDR), firewall sessions, and Active Directory logs to determine the scope of compromise, lateral movement attempts, and compromised assets.

4. Containment & Response Phase

Short-term: Revoke active user sessions, block attacker IP on firewall, and isolate endpoint network segment. Long-term: Apply firewall restriction rules and update endpoint signatures.

5. Recovery Phase

Re-image compromised host from secure backups, reset credentials across Active Directory, restore service operations under enhanced monitoring, and verify system integrity.

6. Closure & Lessons Learned Phase

Document root cause analysis (RCA), update SIEM detection rules to eliminate blind spots, share IOCs with threat intel, and deliver final incident summary report to management.

6. Hardening Recommendations

  • Multi-Factor Authentication (MFA): Enforce mandatory MFA across all external remote access, VPNs, and administrative portals.
  • Account Lockout Policies: Implement threshold lockouts (e.g., lock account for 15 minutes after 5 failed attempts) to mitigate brute force risks.
  • Network Segmentation & IP Whitelisting: Restrict administrative interfaces (RDP, SSH, Management Consoles) to trusted internal management subnets.
  • Least Privilege Enforcement: Audit administrative accounts regularly and enforce Just-In-Time (JIT) access management.
